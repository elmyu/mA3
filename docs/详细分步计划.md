## 三、数据与接口契约（无新增接口改动）

数据库 5 张表：

| 表 | 关键字段 |
|---|---|
| users | id、username、password_hash、role、real_name、gender、age、phone、created_at |
| devices | id、name、status(online/fault/calibrating)、last_calibration_date、location、created_at |
| signal_records | id、patient_id→users、signal_type、sample_rate、data_json、file_path、recorded_at |
| appointments | id、device_id→devices、doctor_id→users、start_time、end_time、status、created_at |
| doctor_schedules | id、doctor_id→users、schedule_date、start_time、end_time、status |

API 清单（全部以 `/api` 为前缀，JWT Bearer 鉴权）：

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| POST | /auth/login | 公开 | 登录，返回 JWT 与用户信息 |
| GET | /auth/me | 登录用户 | 当前用户信息 |
| GET | /signals/my | 患者 | 本人信号列表 |
| GET | /signals/<id>/waveform | 患者本人/医生 | 波形数值 |
| POST | /signals/upload | 患者/医生 | CSV 上传 |
| GET | /doctors/schedules | 患者 | 医生出诊/空闲时间 |
| GET | /patients | 医生/管理员 | 患者列表 |
| GET | /patients/<id>/signals | 医生/管理员 | 患者信息与信号 |
| GET | /devices | 医生/管理员 | 设备台账 |
| PUT | /devices/<id>/status | 医生/管理员 | 修改设备状态 |
| POST | /appointments | 医生 | 创建预约（校验设备状态与时间冲突） |
| GET | /appointments | 医生 | 我的预约 |
| GET/POST | /users | 管理员 | 用户查询/新增 |
| PUT/DELETE | /users/<id> | 管理员 | 用户修改/删除 |
| POST/PUT/DELETE | /devices[/<id>] | 管理员 | 设备录入/修改/删除 |

角色权限矩阵：患者（本人信号、医生排班）；医生（患者调阅、设备台账、设备预约）；管理员（用户管理、设备维护）。前端按角色渲染菜单 + 路由守卫，后端 `role_required` 强制校验，双层隔离。

## 四、测试与验收场景

- T1 认证：三角色账号登录成功；错误密码返回 401；无 token 访问受保护接口返回 401。
- T2 越权：患者 token 访问 /api/patients、/api/devices、/api/users 返回 403；医生访问 /api/users 返回 403。
- T3 患者数据隔离：/api/signals/my 只返回本人记录；波形数值与记录一致。
- T4 医生业务：调阅患者信息与信号；修改设备状态成功；预约空闲设备成功；预约时间冲突或设备故障时返回 400。
- T5 管理员业务：用户/设备增删改查均成功，删除后列表即时刷新。
- T6 上传边界：合法 CSV 生成记录并保存文件；非法格式返回 400；超过 10MB 返回 413。
- T7 前端路由：未登录访问受限页跳 /login；患者直达医生页跳回角色首页；三个角色菜单项正确。
- T8 构建与部署：`pnpm build` 成功；`docker compose up --build` 后 8080 全流程可用；推送 main 后 Actions 绿勾。
